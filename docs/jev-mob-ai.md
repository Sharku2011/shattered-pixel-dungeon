# Jev-directed monster squads

The optional Jev integration chooses a short-lived tactic for each engaged monster squad. It does not ask Jev to select every monster's action on every turn. Once selected, the game resolves attacks and movement locally through each monster's normal combat/pathfinding rules.

## Context and decisions

Each request shares the dungeon depth, branch, floor type/feeling and dimensions; a 13-by-13-or-smaller known terrain window centered on the hero; hero class/subclass, level, health, status effects and equipment type; and characters visible to the hero. The map uses `?` for unknown cells, so unrevealed terrain and secrets are not sent. The map's center coordinates are included so it can be aligned with the absolute character positions.

Each named `squad_<id>` question includes its living members, individual field-of-view map, positions, health, target distance, attack/defense skill, fixed-at-spawn balance multipliers and intelligence profile. The available tactics are `advance`, `flank`, `escort_ranged`, and `hold_range`; `flank` is offered when visible, reachable approach positions span at least two directions, including positions up to four tiles from the hero, and `escort_ranged` only when a ranged squadmate is visible. For `flank` and `escort_ranged`, the same batched request includes one destination question per eligible member, with finite `flank_x_y` or `escort_x_y` choices generated from that member's visible map. This lets Jev select a squad maneuver and its member positions in one API call.

Destination options are included only when at least one compatible movement tactic is available in the same request. Destination options are limited to passable, non-avoided, unoccupied, visible cells reachable by the monster's pathfinder. Flank choices target visible cells within four tiles of the hero, allowing members to route around short obstructions and approach from distinct directions. Escort choices lie between the hero and a visible ranged ally and keep the tank at least two cells from the hero. The response must exactly match a listed option, agree with the selected maneuver, meet the confidence threshold, and remain legal and reachable when checked again. Duplicate destinations and duplicate flank approach sectors are rejected. Missing, stale, conflicting or invalid choices are replaced with distinct locally selected candidates; if no valid candidate exists, the built-in AI handles movement. The game still executes movement and attacks through its own pathfinding and combat rules.

A pending `roles_squad_<id>` question in the same request asks Jev to assign tank/leader, dealer, and support roles based on those realized stats. Role selection is asked once per squad and adds no separate API call. The local stat-based assignment remains active if Jev is unavailable or returns a low-confidence answer. A single System One request can answer multiple newly engaged or expired squads. English identifiers and instructions are used regardless of game language.

On regular floors after floor 1, ordinary monsters are generated as pairs or trios in the same room and within five tiles of their squad anchor. If the room cannot fit all members, the generated group can be smaller. Floor 1 keeps its tutorial-specific individual spawns. Nearby unassigned enemies can still be grouped as a fallback. A newly engaged member alerts nearby squadmates to investigate the same target. Respawned ordinary monsters join a nearby squad with room, or form a new solo group. Bosses, minibosses and immovable characters are not grouped with ordinary monsters. Squad IDs are saved with monsters; older saves without a squad ID are treated as unassigned. Per-monster `hp_stddev`, `damage_stddev`, `accuracy_stddev`, and `speed_stddev` values in `balance/monster_stats.csv` decide which stats vary at spawn. The standard encounter roster uses HP/damage variance through floors 1–10, adds accuracy variance on floors 11–20, then adds speed variance from floor 21 onward. Each resulting multiplier is saved on the monster.

The tank is the initial squad leader and receives +10% experience and +20% loot chance. If the leader dies from floor 16 onward, the toughest living member whose class allows succession in `balance/leader_succession.csv` inherits leadership without those rewards. If succession is unavailable or there is no eligible member, the squad dissolves.

## Intelligence and local behavior

Bosses/minibosses use the strategic profile. Selected trained humanoid, guard, caster and mechanical types use tactical intelligence; other monsters use instinctive behavior. Tactical and strategic monsters can execute Jev flank plans; the tank can execute a Jev escort plan. Instinctive monsters use simple pressure behavior except when explicitly assigned as the escorting tank. Low health by itself never causes the shared hunting AI to flee. Monsters only flee when their own existing AI explicitly enters its fleeing state. If no valid Jev plan is available, the base hunting AI continues to attack or approach as it did before.

## Cost-aware plan cache

A plan is cached for 12 actor-time units. It is invalidated early if the living squad composition changes, the hero crosses a health band, or the hero moves six or more tiles from the plan's anchor. On an invalidation, the first engaged monster batches every currently engaged squad without a fresh plan into one request. A safe local `advance` plan is cached before the call; failed requests, missing/unknown answers, or confidence below `0.45` keep that fallback and do not trigger repeated retries for that same plan. This reduces both request count and prompt size compared with full-floor, per-monster-per-turn queries.

The request is synchronous on the actor thread and has 1.5 second connect/read timeouts, so the game may pause during a tactical refresh. No external LLM fallback is configured; low-confidence Jev answers use the built-in local behavior so the game does not require another provider or key.

## Configure and inspect

Set `TYPESAFE_API_KEY`, pass `-Dtypesafe.api.key=<key>`, or put a local development key in `jev_api_key(pd).txt` in the game's working directory. Override that path with `-Dtypesafe.api.key.file=<path>`. The local key file is ignored by Git and the key is never stored in saves or logs. Without a key, local combat behavior remains available.

Requests append the exact JSON payload (without the Authorization header) to `jev-ai-debug.log`; responses include HTTP status and response JSON. Accepted tactic/confidence pairs are logged as `decision`; destination answers include an acceptance or a rejection with its reason, and executed planned steps are logged as `move_step` or `move_step_blocked`. Low-confidence/unsupported answers are logged as `rejected` and transport/parse failures as `fallback`. Override the log path with `-Dtypesafe.api.debug.log=<path>`.
